# 🛡️ DevOps Guardian

**DevOps Guardian** is a modular, production-ready system designed for comprehensive server infrastructure monitoring, automated log analysis, and smart backup management. The project is tailored for DevOps automation workflows and supports two independent execution interfaces: a high-performance asynchronous Telegram bot and a local Command Line Interface (CLI).

This repository is built as a showcase project for a professional systems administration and automation portfolio.

---

## ✨ Key Features

*   **Infrastructure Monitoring:** Real-time collection of core system metrics including CPU load, RAM utilization, storage availability, and network activity.
*   **Automated Backups:** Packages critical data into secure ZIP archives and automatically purges old archives based on a retention policy.
*   **Dual Interface Modes:** Seamlessly switch between a full-featured Telegram bot and a local CLI utility using command-line arguments.
*   **Asynchronous Architecture:** Built on top of an async engine (`AsyncTeleBot`), ensuring rapid response times even under high concurrent load.
*   **Centralized Configuration:** All critical thresholds, paths, and API keys are strictly managed via an external `config.json` file.
*   **Privileged Execution Safety:** Handles isolated system events and reads restricted Linux log directories securely using managed virtual environment execution.

## ⚙️ Configuration (`config.json`)

Before running the application, you must populate the `config.json` file located in the root directory. Below is the structured format along with a description of each parameter:

```json
{
    "BOT_TOKEN": "YOUR_TELEGRAM_BOT_TOKEN",
    "CHAT_ID": "YOUR_TELEGRAM_CHAT_ID",
    "LOGS_DIR": "./test_logs",
    "BACKUPS_DIR": "./backups",
    "BACKUP_RETENTION": "7"
}
```

### Parameter Breakdown:
*   **`BOT_TOKEN`**: The unique API token generated by Telegram's BotFather for your bot.
*   **`CHAT_ID`**: Your personal Telegram chat ID or the target group/channel ID where alerts will be routed.
*   **`LOGS_DIR`**: The designated system or application directory containing raw log files that the script will automatically scan and analyze.
*   **`BACKUPS_DIR`**: The target directory where the system will generate and store compressed `.zip` backup archives.
*   **`BACKUP_RETENTION`**: The lifespan of backup files (in days). Any backup archive older than this value will be automatically wiped to preserve storage space.

## 🚀 Installation & Setup

### 1. Clone the Repository
Clone the portfolio repository and navigate to the DevOps tool directory:
```bash
git clone https://github.com
cd python-portfolio/devops_guardian
```

### 2. Isolate the Environment (VirtualEnv)
Create and activate an isolated virtual Python environment:
```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Install Dependencies
Install all required external packages, including `pyTelegramBotAPI` and `ruff`:
```bash
pip install --upgrade pip
pip install -r requirements.txt
```

## 🚦 Execution Rules

> ⚠️ **CRITICAL RUNTIME NOTE:** The monitoring modules interact directly with secure low-level Linux kernel interfaces and system log files, which inherently require superuser (`sudo`) privileges.
> 
> To prevent the operating system from ignoring dependencies installed inside your local virtual environment (which triggers `ModuleNotFoundError`), you must execute the script **strictly by pointing `sudo` directly to the Python interpreter inside your `.venv`**.

### Option A. Run as an Asynchronous Telegram Bot:
```bash
sudo .venv/bin/python3 main.py --mode bot
```

### Option B. Run as a Local CLI Tool:
```bash
sudo .venv/bin/python3 main.py --mode cli
```
